# Task Read V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make single-task reads use indexed id/displayId lookup and stable progressive projections so compact reads avoid full task collection scans and unnecessary heavy expansions.

**Architecture:** Add one repository primitive that resolves either internal id or displayId directly from SQLite. Keep full task hydration available for standard/full compatibility, but add a lightweight row projection path for minimal/summary. Route `/api/tasks/:id` through that repository primitive and keep response shaping centralized in the existing `toTaskResponse` contract.

**Tech Stack:** TypeScript, Express, better-sqlite3, Node test runner/tsx.

## Global Constraints

- Work only in the managed DevFlow worktree for this session.
- No hardcoded machine-specific repository path in source or docs.
- Preserve existing standard/full API behavior.
- Minimal/summary are explicit stable contracts, not heuristic truncation.
- Avoid N+1 relation queries and avoid loading attachments/logs/agent-run history in compact modes unless required by the contract.
- Focused verification first; full verification only at final milestone.
